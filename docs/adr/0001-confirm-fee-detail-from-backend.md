# ADR 0001 — 下单页费用明细改为后台配置的「名称 + 金额」列表

- 日期：2026-11-05
- 状态：已采纳

## 背景

下单确认页（`confirm-page`）原先由前端硬编码四档单价与固定押金，只呈现「大字单价 + 小计 + 押金」三层信息：

- 单价来源 `confPeriodBase`（前端常量），与车辆列表价是两套数据；
- 押金是全局常量，不随档位变化；
- 没有税费概念（全仓库无 `ppn` / `tax` / `vat`）。

运营需要按国家/活动配置增值税与其他收费项，硬编码意味着每次调整都要发版。

## 决定

1. 费用明细改由后台**按档位**下发一组「名称 + 金额」条目，前端只负责逐行展示、求和与乘算；
2. 明细名称**原样展示**，不进入 i18n；
3. 押金**按档位单独配置**，不塞进明细数组，固定展示为最后一行；
4. 合计 = Σ明细 × 时长数量 + 押金；前端不做税费反推，也不做二次取整；
5. 移除页面上的「小计」与「大字单价」条，页面只保留「档位选择 → 明细 → 时长 → 底部合计」一条信息链。

## 理由

- 「名称 + 金额」是最小契约，后台可自由增删行（增值税、服务费、优惠）而不用改前端；
- 押金可退、租金一次性，两者语义不同，按档位分别配置更贴近真实商品配置；
- 去掉页面内重复的汇总（大字单价 / 小计 / 底部合计三处金额），减少口径不一致的风险。

## 代价

- 前端失去对金额组成的类型约束，依赖后台数据正确性；
- 明细名称不翻译，切换语言时需运营下发对应语言文案；
- 原型阶段用 `confFeePlans` 常量模拟接口数据，接入真实接口时需要一次数据结构对齐。
